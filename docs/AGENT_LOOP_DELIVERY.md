## 实际处理路径

基础分析与目标核账 → 建立验证任务 → 规划/取待执行任务 → 窄字段查询 → 三值评估及子群体 → 回到规划。没有必要可执行任务后生成报告和一次模型解释；解释中的新判断进入同一循环。最终发布不再调用自由文本生成器，避免再次引入未核验推断。

TaskProposal携带goal_id、cohort、expression、ALL/ANY及可选已注册rule_id；没有范围、SQL、任意关系或单位覆盖入口。模型只能选择本轮已有或本轮派生的记录群体。所有原始记录仍通过父产物、record_id、源文件哈希和行位置追溯。

ALL与ANY分别定义支持、反驳、未知；空群体为未定，不把无样本称为“全部满足”。结果保留完整满足/不满足/未知子群体；支持或反驳只对明确谓词成立，不能证明任意模型文字、因果或责任。

## SPF自动深入规则

- codeUsrSpfSw条件不满足的实际未生效条目：继续读取selLayerNum/ueLayerNum的终端形态及compFlag服务身份。即使模型未配置也执行已注册规则。
- 形态与服务身份均满足仍关闭：保留交集群体，指出互斥或上游决策的字段/判据尚未提供，不能直接确认为互斥。
- 五条件满足但实际关闭：保留残余群体，分别查spfFreqEnFlag、spfFreqCdtEnFlag。筛选阶段标志不能直接替代实际生效状态或确认根因。
- 条件缺失：仅在阻碍完整规则判断时自动补查；如果另一必要条件已明确失败，不因无关缺测强迫全范围继续查询。

实际生效比例仍以全部业务有效条目为分母，包含flag未知；原因条件可以重叠。用户级原因比例和跨会话拼接没有开放。

## 恢复、预算与复用

查询完成先持久化产物和账本，再进行评估；中断恢复验证哈希后只补后续评估。任务指纹与查询指纹分离，相同群体/表达式查询可支持ALL与ANY两种评估，无需重新扫描。重复等价任务且无新进展停止为NO_PROGRESS。

默认追加验证QueryPlan最多12次、验证规划最多6次；规划/验证/解释合计最多12次模型调用，可在规定范围内配置。验证任务结构/来源无效时允许一次反馈修复，同样消耗规划及模型预算，不执行半个无效批次。它们共享原有累计时间预算，重试不清零；单查询最多30秒，DuckDB限制512MB。基础分析、缺口目录读取等查询另计日志，不把追加QueryPlan上限冒称整个分析的SQL总数。整体进程RSS不受512MB硬限制。

已发布结果保持不可变，修改预算或配置后重新提问生成新动作。中断操作可用原动作重试；已发布的技术失败或预算不足报告不会被静默覆盖。

## 合成规模基准

脚本：`scripts/benchmark_verification.py`。复用已有数据集，不重新ETL。两轮验证由模拟规划器在看到上一轮结果后提出，第一轮反驳“未生效条目开关全部打开”，第二轮在反例群体核验逐行SINR门限；实际执行了两条追加QueryPlan，不是预先计算后模拟回环。

| 基础比例分析 | 53.804秒；100ms采样峰值RSS 764563456字节（约729 MiB） |

## 现场复验建议

1. 重启工作台；询问“SPF未生效原因是什么，各条件占未生效条目和全部有效条目的比例是多少”。
2. 对比五条件计数、实际flag分布和原有分母；查看是否出现预期的追加验证阶段。
3. 在“持续验证任务、停止原因及缺口”保存verification_loop；核对任务群体、计数、证据引用及缺口数量。
4. 记录action_id、performance.txt中的verification_stop_reason/verification_queries/verification_planner_calls，以及模型purpose=verify的安全响应元数据。
5. 如果是预算/模型/查询失败，应显示分析未完成，不应显示数据不足；现场反馈无需提供API密钥。
