# AH-005：计划语义校验滞后与解释拒绝原因缺失

GitHub Issue：https://github.com/koukou-33/Analysis-Helper/issues/1

## 已确认现象

模型把 CONDITION_COUNT 的条件写进 condition，conditions 为空。结构校验通过，但执行到条件计数时出现 ValueError: CONDITION_COUNT needs 1–20 conditions。当前仅展示异常类型，未在模型规划修复阶段指出字段位置。

同轮解释连续三次校验失败，只显示通用提示。旧版本没有保存被拒绝的模型返回或具体失败原因，无法追溯究竟是列、单位、证据行还是引用错误。计划失败后仅有时序证据可供解释，不能因此断言解释错误的具体原因。

## 本次修复

- Step 在执行前验证各操作的必填字段、CONDITION_COUNT 条件字典与 ID、GROUP_AGG 输出冲突、时间范围和关联窗口。
- 规划修复反馈包含校验位置和规则；修复次数仍限制为两次，失败后回退基础计划。
- 解释独立校验，区分缺字段、无效列表、未知产物、未支持列、单位错误、无效行键、非法数值、证据不匹配及未绑定引用。
- 解释错误码和数组位置写入结果 validation_errors，以及 performance.txt 的 validation 事件；不记录密钥、原始模型响应或证据数值。
- 明确告知模型允许的数值列和单位，以及可以用空列表表达证据不足；最终提示展示错误码和位置。

## 验收

错误的条件计数计划在执行前拒绝；模型收到具体修复位置；解释错误能按类别定位并持久化；合法证据仍通过；失败时保留基础统计，不发布未经校验的模型解释。

52 项 unittest/AppTest 回归通过，包括历史条件计数错误的结构复现、模型修复反馈、连续三次解释拒绝及诊断记录恢复。历史原始返回未保存，不能把新测试中的错误类别当作旧请求的实际原因；真实模型仍需重新分析复验。
