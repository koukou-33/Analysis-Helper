# AH-010：模型结构化输出失败、诊断信息不足及完成状态误导

记录日期：2026-10-27。状态：用户补充现场信息后恢复分析与方案记录；根因未确认，代码修复与现场复验待实施。当前为仓库内 Issue，未创建 GitHub 在线 Issue。关联：详设 §18、[连续深挖修改计划](../CONTINUOUS_ANALYSIS_IMPLEMENTATION_PLAN.md) P0/P1/P3/P6；P0为优先开发阶段。

## 现场证据

问题：“这份数据中的SPF生效情况怎么样？”用户报告实际模型为 glm-5.3-flash，服务端点、版本及响应原文尚未提供，不推断具体供应商接口能力。

此前通知两次“模型返回的结构化输出无效”。两次 chat 合计287.594秒，约占总耗时93.1%；单阶段耗时可能包括HTTP重试，不能当作单次推理时长。diagnosis OK仅表示外层返回；当前空需求列表也被判为FACTS_READY，不能证明业务问题完成。

## 假设与代码依据

假设H1：content为null/空值，可能只有推理内容而无最终输出。假设H2：输出预算耗尽或其他限制使JSON截断。均待证据确认，不称为特定模型通病。

services.py 将 content 非字符串、JSON解析失败、非对象、choices/message/content缺失统一转换为ServiceError。若上述通知与本轮日志对应，外层响应JSON已经成功返回，失败发生在提取/解析最终content时。当前请求没有显式输出token上限或推理配置；当前日志不记录finish_reason、token usage和内容类型，不能区分H1/H2。也可能是夹杂正文、结构不兼容等其他原因。

embedding错误独立定位，不由H1/H2解释。requirement_count=0与业务完成状态问题独立修复。

## 分步解决方案（待实施）

### S1：先增加可验证的诊断信息

按trace_id及plan/explain用途记录：HTTP状态、请求ID、attempt、耗时、模型标识、choices数量、finish_reason、content类型/长度/空值、可选reasoning_content存在性及长度、服务返回的usage（含可选推理token）、JSON错误类型与位置。区分CONTENT_EMPTY、OUTPUT_TRUNCATED、INVALID_JSON、RESPONSE_SHAPE、HTTP/TIMEOUT等错误；没有截断标记时不能仅凭解析错误位置断言截断。

不默认保存密钥、请求头、完整prompt、业务原文或推理正文。允许服务字段缺失，遥测失败不破坏业务结果。UI展示可操作错误及追踪ID。

### S2：按能力配置输出与推理预算

建立显式服务能力配置：输出限制参数名、最大允许值、是否支持推理开关/强度及结构化输出模式。参数名称和推理token是否计入输出额度须按实际端点文档确认；不能向所有兼容接口无差别发送同一厂商参数。

若确认仅推理消耗预算而无最终content，针对规划/结构化解释降低推理强度或关闭推理（仅服务支持时），或在模型上下文与服务限额允许范围内增加输出预算。规划、解释分别配置预算，不能只增加HTTP超时。

若确认输出截断，优先缩小输出结构/拆分任务，按上限有界增加输出预算，重新生成完整JSON。仅当真实接口支持时启用严格schema输出；json_object不等于通过业务schema验证，也不能防止所有长度截断。

### S3：控制输入和输出规模

规划只发送问题相关字段及依赖字段、规则和必要schema，记录裁剪策略及未覆盖状态，不默认携带数千字段。解释发送完整确定性业务汇总和有界证据引用，不把全量明细交给模型；不能以随意截取表头10行替代业务总体。

拆分大型解释任务，优先短的假设/引用结构；精确数字由程序计算并渲染。已知SPF结构化核验不依赖通用模型规划即可完成。

### S4：有界恢复，禁止伪造修复

空content或截断时只允许在明确调整预算/输出规模后进行有限重试（建议最多一次，具体上限配置），共享端到端时间预算；不嵌套放大HTTP重试与结构修复轮数。记录每次策略及结果。

不拼接不完整JSON，不凭空补齐括号/字段后发布，不把reasoning_content当作最终答案，不无限请求“继续”。持续失败时保留已验证确定性报告并标记模型解释失败；切换模型需用户配置，不静默更换服务或外发数据。

### S5：业务完成状态与独立embedding修复

分离运行是否返回、业务目标完成度、模型解释状态。空需求列表不自动表示SPF业务完成，模型失败也不抹去通过核验的确定性指标。与连续深挖P1/P3共用实现。

embedding单独核对接口、模型、鉴权及向量格式，保留BM25降级。不假定chat模型可用作embedding，不因embedding失败阻断确定性核验。

## 验收

模拟响应覆盖null、空字符串、只有reasoning_content、finish_reason=length且不完整JSON、正常结束但畸形JSON、字段缺失、合法JSON对象、完整markdown代码块、非法数组及HTTP超时/重试。验证错误分类、无敏感内容日志、有界重试、服务不支持参数时明确报错、不发布未校验内容。

业务验收：模型失败仍输出正确条目生效率及未知数量；零需求不误报整体完成。现场复验对照同一问题和范围的finish_reason、usage、content元数据与总耗时，不以模拟测试宣称实际模型根因已修复。
