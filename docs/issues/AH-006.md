# AH-006：跨步骤字段来源与四流解释约束

GitHub Issue：https://github.com/koukou-33/Analysis-Helper/issues/2

现场复验发现：聚合步骤产生 gain_avg，但后续 COMPARE 仍选择原始 stream 表；计划结构合法却在执行时报 Unknown or unavailable field。另有模型解释将已确认的 instBfSinrGain[0..3] 误读为 UNCONFIRMED_ARRAY。

现有知识资料其实已列出该字段为用户明确的四流增益，但随后对“其余短数组”的通用描述被模型错误套用。2026-10-26 用户确认：[0..3] 对应第一至第四流，分类 STREAM；正常通常依次递减，倒序仅待核查，不直接判定故障；增益全空只报告缺测，不推断采集故障，不要求重复确认四流映射。

实施：按计划顺序推导 resource/stream、聚合结果、条件明细与计数结果的字段集合；分组、聚合、比较和时间关联字段必须来自指定 source。条件中真正缺失的特性字段仍返回 UNKNOWN，已存在于其他关系中的字段误引用应报 FIELD_SOURCE_MISMATCH，反馈字段位置及可用关系，要求模型修复 source 和 depends_on。规划及执行入口均校验，不扫描明细数据。

知识文档及映射版本已更新，同时纠正知识文档中旧日期格式为 `%Y-%m-%d`。规划和解释系统消息包含独立的已确认四流规则，优先于检索片段和历史解释。无有效四流增益时使用确定性缺测说明，保留查询统计，但不调用自由文本解释或视觉比对，不发布故障假设。此分支也会抑制其他指标的自由文本解释，作为当前保守策略；原始统计仍可查看。有增益样本时使用提示约束，不能保证穷尽语义错误，模型假设仍不属于事实。

验证：57 项 unittest/AppTest 全部通过，涵盖聚合字段误引用、条件明细与汇总区别、真正缺失字段 UNKNOWN、模型字段来源修复反馈及全缺测分支。2026-10-26 经用户授权使用真实 DeepSeek 复验：前两次计划格式错误被反馈修复，第三次成功执行聚合和条件计数，notices 为空；解释使用确定性缺测说明，不产生自由文本假设。历史结果不改写，工作台已重启加载新版。
