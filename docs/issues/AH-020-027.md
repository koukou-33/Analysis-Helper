## AH-020 / P0：进度持久化失败中止整次分析

定位：agent.py 的 save_progress 先更新内存，再写固定 .tmp 文件，最后 os.replace；无有限重试或持久化错误分类。timed_node 的 finally 再次保存，可能覆盖业务异常。journal 保存计划、执行完成标志、artifact 引用、模型次数、预算、验证队列，不能当成普通可丢弃日志。

设计与实现方案：

1. 将关键动作恢复状态存入 SessionStore 的 SQLite 事务表，按 session_id/action_id/request_hash/revision 绑定；增加版本检查，限制同一动作并发写入。与 LangGraph checkpoint 的职责和恢复顺序明确，不能维护两个互相矛盾的权威状态。
2. 模型调用预算预留先提交；完整证据关闭并校验哈希后再提交产物引用及步骤完成状态；解释消费与入队一起提交。崩溃后允许存在未引用的孤立产物，但不能出现已完成引用指向不完整文件。
3. 有界重试仅用于可能短暂恢复的锁/共享失败，计入总预算；持久性权限错误、磁盘满不无限重试。关键恢复状态始终无法提交时安全停止并给出 STORAGE_FAILURE，保留已持久化证据，不伪装成数据不足或成功。
4. JSON 进度文件改为可选诊断导出；其失败只提示日志降级，不能否决已成功持久化的业务分析。保留原始异常，finally 的遥测故障不能覆盖它。
5. 旧 journal 在校验动作、请求、数据版本及已有产物后迁移；损坏记录明确报告，不能静默重置预算或当作新动作。
6. 记录失败阶段、操作、errno/winerror、重试次数、耗时和脱敏路径类型（输入CSV/配置/journal/产物/注册库）。区分读取输入失败和替换进度失败。现有数据集若使用快照/数据库分析，外部 CSV 打开是否有关需按失败路径验证；不要求关闭 Windows 系统服务。

验收：模拟短暂占用后恢复、持续拒绝访问、数据库锁、磁盘写入失败、进程重启、旧 journal 损坏；不得重复认领完成产物、重置调用预算或遮蔽原始异常。现场 Windows 实机占用用例另行复验。

参考：[Microsoft MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)、[CreateFileW 共享模式](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)。打开句柄的共享模式可能阻止重命名；访问拒绝也可能涉及权限，单凭错误名不能确认具体进程。

## AH-021 / P0：时序最终行序无保证

定位：charts.metric_time_series 的 lag 和累计 sum 已在 OVER 内按 event_ts 排序；但 trend 的 CREATE TABLE AS SELECT 没有外层 ORDER BY，export_relation 又执行无 ORDER BY 的 SELECT *。app.py 直接按 Parquet 前2000行交给 px.line，未重新排序。相关 EXISTS 可能影响物理执行顺序，但不能因此认定窗口值必然计算错误。

方案：为时序产物声明 order_by=[logicCellId,ue_uid,event_ts]，在最终导出 SELECT 实施显式排序，并在绘图入口按对象、分段、时间稳定排序。窗口自身继续显式排序；同时间多值继续按原规则合并或标缺口，不能用 record_id 伪造时间先后。对分组输出定义稳定键，对原始记录预览可用 record_id 打破同时间展示顺序，但不能据此产生因果或时序结论。不能只在中间建表补 ORDER BY 就宣称所有下游有序。

验收：乱序输入、多小区/会话、相关 EXISTS、不同线程设置、同时间冲突及质量断点；窗口结果、完整导出顺序、预览和图形顺序分别断言。

参考：[DuckDB Window Functions](https://www.duckdb.org/docs/current/sql/functions/window_functions) 明确窗口计算排序不保证 SELECT 输出排序；[Order Preservation](https://duckdb.org/docs/current/sql/dialect/order_preservation) 说明不同算子的保序边界。

## AH-022 / P1：头部预览替代了全范围展示

定位：plans.export_relation 只累计最先读取的100行；app.py 图形只读第一个2000行 batch。当前已有“预览不代表全量分布”提示，但无法观察后续用户、时间段和少数状态。预览甚至未必是按时间排列的最早记录。

方案：

- 完整证据保留不变。统计摘要用完整结果计算，绝不能用预览计算占比、极值或趋势。
- 表格按问题相关的小区/会话/状态或时间区间分层，使用稳定键确定性取样；展示方法、样本数、完整行数、覆盖和未覆盖组数。称“覆盖预览”，不宣称它是无偏统计样本。
- 图形在完整对象/segment 内按时间降采样，保留首末、局部极值、缺口与段边界；先选择对象/时间再绘图。上限不足覆盖全部对象时提示筛选，不悄悄遗漏后部会话。降采样不得跨缺口连线，也不改变完整证据的统计口径。
- 样例保留原记录或分组键和 artifact_id；聚合结果不得套用原始记录行数含义。

验收：超过100行/2000点、后半段唯一突变、少数状态、多于预览额度的分组、极值和断点；输出可重复、覆盖边界可见、全量摘要不随预览额度变化。

## AH-023 / P1：通用算子结果没有确定性报告契约

定位：agent.report_node 对通用 artifacts 只专门处理 METRIC_TIME_SERIES.statistics，未使用其 group_statistics；但 SPF 的 feature_report、会话状态摘要和 loop_report 已存在，不能说整个报告只处理一种算子。用户所述 MERIC_TIME_SERIES/HRGROUP_AGG 对应本地 METRIC_TIME_SERIES/GROUP_AGG。

建议引入 EvidenceSummary 和算子报告注册表，报表由查询执行后的确定性摘要生成；模型失效仍应回答能由证据确定的业务问题。

| 算子 | 需要输出的事实及限制 |
| --- | --- |
| FILTER | 来源关系总行数、保留/排除/条件未知数、筛选条件；占比绑定该步骤来源，不自动以全数据为分母 |
| GROUP_AGG | 分组键、聚合函数、样本数/有效值数、结果与单位；不得平均各组均值来冒充总体均值 |
| CONDITION_COUNT | 条件定义、True/False/Unknown及明确分母；重叠条件不能累加为原因贡献 |
| COMPARE | 当前实现是组内 max-min，不是双数据集比较；报告范围、有效样本与源字段单位，少于两有效值不判定差异 |
| TIME_SLICE | 时间端点口径、来源范围、命中记录/时间覆盖；不擅自扩范围 |
| TEMPORAL_RELATE | 对象键、前向窗口、关联True/False/Unknown计数；目前语义为是否存在，不是事件配对数量，不确认因果 |
| METRIC_TIME_SERIES | 分小区/会话的首末有效值、极值、覆盖/缺口、单位；全局极值不能替代各小区变化回答 |

报告按问题目标和证据依赖组织，避免逐个倾倒中间算子或重复统计。派生关系的分母、父群体和作用域需可回查；暂无摘要支持的产物明确标记，不默认算作问题已回答。

验收：每类算子与串联计划、空结果、零分母、全未知、派生群体、非dB字段、多组统计；关闭模型时仍有相关的确定性回答。

## AH-024 / P1：趋势意图解析分散

定位：question_scope.parse_question 支持“趋势/变化/曲线/折线/时序”，cross_layer 只识别“趋势/trend”，app 的状态图又使用另一组词。相同问题走不同路径可能产生不同结果。

方案：统一意图对象（时间演变、状态切换、分布/比较等）及版本，在确认页展示并保存，执行和展示读取确认请求，不重新各自扫关键词。扩充“随时间/走势/升降/波动”等表达，处理否定和仅请求图形的区别；模型只提供候选，不可改已确认范围。突变、异常阈值未知时只能展示变化量和缺口，不能直接定义异常。

验收加入用户原句，并覆盖中文近义、英文、否定表达、仅分布问题。原句已有“变化”，其跨CRNTI身份需求由 AH-027 单独验收，不能以扩词表替代。

## AH-025 / P1：计划限制没有进入正常回答

定位：QueryPlan 有 limitations，result 和 artifact 内计划也有保存；app 仅在高级 st.json(plan) 时可见，没有正文呈现。故“从不展示”应收窄为“正常报告不展示”。

方案：将计划限制、字段单位缺口、产物覆盖限制、验证停止原因分别带来源收集并去重，放入正常回答的限制说明及证据详情，也传给模型。模型提出的 limitations 标为计划自述，不提升为已验证数据缺失；“用户级占比尚未支持”等影响回答的限制必须醒目。已验证解决的限制可标已解决，保留原计划审计记录。

验收：无须打开技术详情即可看到限制；历史结果兼容；模型故障仍显示；避免重复或把技术失败描述成数据不存在。

## AH-026 / P1：模型通用证据只有10行，摘要及数值校验无法扩展

定位：explain 的通用 evidence 只有 artifact_id、row_count、preview[:10]；没有 operator、schema、单位、作用域或全量统计。与此同时已有 feature_summary、session_states、verification_state 等专用摘要，不能说所有模型上下文均无摘要。explanation.UNITS 是静态白名单，comparison_diff 固定 dB，新增字段/聚合别名会被拒绝或使用错误单位。

方案：

1. 模型与确定性报告共用 AH-023 的全量证据摘要，包含算子、来源字段、分组、指标口径、总行数/空值数、覆盖/分母、单位、缺口、父产物和确认请求绑定。
2. 摘要作为有哈希、可回查的独立证据或受结果哈希保护的契约持久化，定义 summary_id/metric_key 或唯一行键引用。核验从完整产物计算值，而不是信任模型或样例。
3. 单位由已确认字段元数据和算子语义传播（计数/比例/差值分别处理），未知则明确 RAW_VALUE_ONLY；允许列由校验过的计划输出 schema 产生，不能开放任意模型声称的字段。
4. 样例从 AH-022 取得并明确只作展示。按问题与依赖选择摘要，限制整个上下文的字符/token预算，而不是只增大每个产物行数。高基数分组分页/筛选；省略内容必须标记并允许范围内定向查询。
5. 需要验证的判断缺少充分摘要时回到查询循环，未完成就说明具体原因；不能对10行样例概括完整数据。不会为获得更多上下文而放宽证据核验。

验收：关键组不在前10行、普通TA/新增字段、错误单位、伪造摘要/引用、模型截断、宽表多产物上下文上限、全量核账、模型关闭回退。

## AH-027 / P1：本次分析的单用户跨CRNTI身份声明

本项由用户原句进一步确认，非全局身份规则。CRNTI/ue_uid 仍是原始接入身份和观测会话，不能改写底层会话划分。

方案：AnalysisRequest 增加经用户确认的身份说明，记录类型 USER_ASSERTED_SINGLE_SUBJECT、作用范围/父群体/数据指纹、原始说明、确认时刻和修订哈希。声明只约束当前确认范围内记录，不覆盖范围外或其他数据集；改变范围要重新确认。解析到“所有CRNTI”不得选取单个CRNTI过滤，继承界面筛选的冲突需明确展示。

汇总视角允许将不同CRNTI/小区/会话归为本次同一分析对象，同时完整保留各段来源。跨小区TA展示分段时间图、各段首末/极值/覆盖和可比较差值；段间不连线，不推断接入间隔内的轨迹、移动距离或无观测切换时间。相同时间多小区观测并列显示，不强行确定先后；TA单位/缩放仍按映射确认状态处理。报告注明“依据用户本次确认的身份说明”，不得称为数据自动证明。

验收：原句 → 确认页展示身份说明 → 多小区多CRNTI分段查询 → 回查原始记录；无说明时保持原会话隔离；新动作/新范围不自动继承；有父群体时不超出父群体。

## 本地实施及验证结果（2026-11-09）

R1～R4已实施。新增 progress.py、result_summary.py、preview.py、chart_preview.py、intents.py，修改 agent/plans/charts/explanation/provenance/确认页与证据画布；具体实现契约见详设§28。

- action_progress事务保存恢复状态，预算预留先提交，旧JSON按动作迁移；并发修订拒绝覆盖。取消进度JSON替换；SQLite持续锁或磁盘故障仍安全停止。阶段遥测失败不覆盖原异常。
- 全量产物明确排序；通用算子报告、摘要哈希、动态列单位和摘要fact_id引用接入；COMPARE的单位不再固定为dB。
- 表格覆盖预览、按对象选择的时序降采样、计划限制及解释上下文预算接入；SPF专用报告和旧产物保持兼容。
- 本次单用户身份声明显式勾选，范围/指纹随请求哈希绑定；多CRNTI、多小区保留独立接入来源和分段图。没有说明时不自动合并身份。

148项完整离线回归通过（225.778秒），包含6项新增可靠性测试；最终统一确认意图及跨小区用例定向复验2项通过（5.964秒）。新增测试覆盖锁失败后内存/持久化预算不变、并发写拒绝、旧进度迁移和损坏、稳定覆盖采样、全量摘要与单位/哈希校验、乱序时序的末尾极值和缺口、跨CRNTI身份说明仅本次生效。原有六类算子、持续验证循环和AppTest也通过。初轮发现并修复SQLite连接关闭、DuckDB视图参数绑定、解释上下文列表兼容问题。

性能复现：`.venv\Scripts\python.exe -m scripts.benchmark_evidence`。12万行、10列、1000组，512MB内存限制、2线程；排序+Parquet导出+覆盖预览4.2808秒，摘要0.0461秒，总计4.3269秒，预览98行，Parquet约4.18MB。数据及输出位于忽略的workspace_storage/evidence_benchmark，未读取现场数据。

R5的本地回归与上述结果规模基准已完成；现场3875万补充行/23GB数据库、真实模型及Excel占用现象未复验，不据此关闭现场问题。表格样例不保证无偏，高基数组/分段超出上限时明确标记并要求筛选；没有实施跨段插值、自动根因或物理单位换算。本轮代码、测试及文档纳入交付提交；现场问题仍保留待复验状态。
