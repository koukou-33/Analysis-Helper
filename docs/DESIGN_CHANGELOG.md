## 基线：数据规则与图文案例整合（日期未单独记录）

- 固定单文件保序流控，完整块全留，仅由原始 CRNTI 缺失触发不完整块截断；日期来自 uwData + uwTime。
- 固定输入快照、完全相同文件去重、部分加载成功继续分析；不同数据集独立。
- 案例采用 Markdown + images，人工审核发布；相似案例可直接提出并展示相似点、差异和未验证项，不自动确认为当前根因。
- 后续质量和流数规则以主文档现行定义为准，不能从早期讨论恢复已替代的可疑比例切换策略。
- 原始依据：快照原第 1～8 章；查询填写样式见 [query_template_style.md](../query_template_style.md)。

## 2026-10-28：记录条件验证循环

## 2026-11-10：统一专家循环与单向解释/报告

- 确认顶层 `START → plan → agent loop → explain → report → END`。
- loop 统一调度检索、统计、条件、比较、时序及验证，逐轮核账目标；退出时冻结证据包。
- explain 基于已取得结果综合解释与结论，不再返回 loop；report 展开每步分析、数据及结论关联。
- 区分问题闭环、资料/口径受限、执行未完成；新追问携带原问题、补充问题与结构化历史创建新动作。
- 状态：设计已确认，统一图、冻结包与输出迁移待实施。现有查询、证据、恢复与预算能力作为复用基础。
- 原始依据：快照原第 5、19、30 章；当前完整方案见主文档第 5、7、8 章。

## 2026-11-13：多对象意图、秒内观测与双层审核实施

- 主设计更新至v3.5，现行请求改为LLM结构化意图加字段/范围校验；明确多小区和配对对象可直接执行，身份声明绑定本次成员。模型不可用显示确定性回退，不声称理解所有复杂问法。

- 工具结构错误保存具体字段和安全摘要，并有界反馈修复；技术故障、数据限制、未覆盖任务分别保留。数据审核PASS与模型任务SUPPORTED均不代表根因被独立证明。
