# SDS v3.3 与当前实现差异评审

日期：2026-10-26。评审输入：`E:/Project/5g_srs_diagnostic_agent_design_spec (2).md`；基线：仓库详设及当前实现。仅形成评审，不改动运行代码或覆盖两份详设。

## 1. 本轮用户已确认的规则

1. 流控继续按文件内原始顺序划分连续 uwTtiCnt1 块；完整块全部保留，只有存在原始 CRNTI 缺失时才截断。新版 §5.3 的完整多行块删尾和按计数值合并不连续块不采用。
2. `instSubfGain` 为新版笔误，仍使用 `instBfSinrGain[0..3]`。
3. `ueLayerNum` 表示实际流数，目前取值 1、2、4，未来可能出现 8。有效流下标仍以 `ueLayerNum` 为准，不以 `selLayerNum` 替代；不依赖空值、恒零或极值猜测未激活。
4. 继续使用 `logicCellId` 作为小区身份，`phyCellInst` 保留辅助字段。
5. 缺测与越界分别计数；允许新增 RSRP/NI 可疑子类型，不能把 NULL 当作越界。
6. 四类责任主体用于给出有依据的优先排查方向，未观察到上游证据时标记未核查，不声称“L1 无责”或直接确认根因。确认根因需要明确判据或人工确认。
7. ueLayerNum 缺失或为 0 时直接标记异常数据，不使用增益分布推测流数。此类记录退出全部业务分析，包括 RSRP、NI、流及业务汇总，保留在异常数据明细和质量计数中。ueLayerNum=8 而 CSV 仅有四列时报告“仅覆盖前四流”，不能将配置流数改写成 4。
8. 用户已在 nr_srs_field_mapping.md 补充部分责任层归属，以实际映射为准，不套用新版示例归属。未填写项继续待补充；示例门限尚未获确认为生产判据。
9. 同侪比较仅在用户明确要求时触发，模型和场景规则不得自行启用。采用同小区、同一分钟时间窗、排除目标 UE，并限定相同 RB 区间、Slot 和符号位置。不同用户可能存在显著空间差异，且这种差异未必能从 L1 测量中识别；满足上述筛选条件也不构成空间可比或因果归属的证明。
10. 同侪比较的起始符号字段确定为 `ueSymPos`，一般只有一个符号；不将“一般一个符号”视为所有记录均保证单符号。
11. 其他非法 ueLayerNum 值（负数、非整数及非支持值）统一归异常数据并排除全部业务分析；8 是已明确的未来配置，四列输入按部分覆盖处理，不混作非法值。
12. 可疑记录整行退出全部业务统计，取代旧实现“有限数值全部参与”的口径。例如 RSRP 越界而 NI、增益正常时，该记录的 NI、增益也不参与业务统计。保留原始记录、质量计数和审计信息；替换 INCLUDE_ALL_NUMERIC 策略。
13. 文档需求仅覆盖当前问题相关内容。采用评审建议：相似案例可展示，必要判据满足才称实测支持，不自动确认根因；版本来源冲突时提示用户选择，不静默覆盖人工指定。
14. 按用户问题决定所需指标及数据不足判断。RSRP、NI、增益均不是每次必查项；任何单项全空都不能自动阻断其他有充分数据的问题分析。

## 3. 新版示例和设计约束需纠正的地方

### SQL 示例

- §5.3 的 MAX 内嵌 ROW_NUMBER 窗口表达式应拆成分层 CTE；不能将示例原样用于 DuckDB。
- 同一 uwTtiCnt1 在文件内可能再次出现，不能以 `(source_file, uwTtiCnt1)` 代替连续块 ID。
- 新版按解析后的 crnti 判 NULL，会把原始非空但解析失败与真正缺失混同；流控继续使用原始存在性。
- §3.2 的示例从 l4_cell_tf_summary 查询 srsUeNiDb 和 data_quality_tag，但 §5.4 的该汇总表没有这两列。应从范围明细聚合，或对汇总值使用正确分母加权，不能对组均值再简单平均。
- 案例 SQL 的 `{phyCellInst}` 必须使用绑定参数。当前手工 SQL 只允许 scoped resource/stream，不能为兼容示例直接开放全量底层表。
- 固定 Slot 3/8/13/18 的 S 时隙规则需要实际 TDD 配置，不能仅凭 30 kHz 将其推广为通用事实。

### 全列与覆盖率

- CSV 为文本行格式，前置列扫描不是免费优化；SUMMARIZE 再正式加载可能增加一次全量读取。应以实际基准选择一次扫描建账或二遍扫描，不承诺毫秒级 ETL。
- 全空列的判断需覆盖整个快照；不能因为单文件为空就在合并数据集删除该列。保留原始快照及全量表头审计信息。
- 三态不足以表达“有原始值但全部解析失败”“本轮范围没有数据”“尚未查询”“查询失败”“未支持的数组计算”。建议分开存储字段存在性、有效性和查询执行状态。
- 字段出现在 SQL 中不等于已完成有效核查：仅 WHERE 使用、零行结果、失败 SQL、SELECT *、别名和派生列均需结合计划来源、成功产物与统计目的判断。
- 目前补充数值能力针对标量；波束数组和非数值列需要明确支持的分析算子，不能一律加入自动数值聚合。
- “所有召回文档正文出现的字段”可能包含对照案例或排除项；需求应有文档出处、相关性和核查目的，避免无界扩大任务。

### 已有可靠性措施应保留

- 保留已修复的生产文件名、`%Y-%m-%d` 日期和四流字段映射，不能退回仅 NR_SRS.*.csv。
- 保留内容哈希、输入契约、ETL 版本及完成清单校验；新版“路径+大小+mtime，截短 12 位”只能作快速候选索引，不应替代数据身份。
- 保留精确依赖锁定，不降级为仅最低版本要求。
- 完整结果保持外部 Parquet，检查点保存引用，避免将宽表复制到 SQLite 状态。
- 0 秒恢复、<50ms 挂载、100% 查询等应表述为目标/适用条件，不作为未经基准验证的绝对保证。
- 不必因新版目录图立即搬迁现有 srs_helper 包；优先按功能演进，目录重构可单独进行。
- Markdown JSON 外壳及 artifact: 引用前缀兼容仍待实现，可纳入模型输出兼容阶段，不能因新版未提及而漏掉。

## 4. 尚需明确的业务细节及建议默认值

1. 已确认非法 ueLayerNum 退出全部业务分析，仅保留异常明细及质量统计；8 流四列标记部分覆盖。尽管字段说明同时存在 selLayerNum（终端发射流数）与 ueLayerNum（终端总流数），用户已确认流筛选仍以 ueLayerNum 为准。配置范围内全空/零值不额外删流。
2. 已收到部分责任层归属；剩余空白项不自动强制分类。Markdown 与机器 JSON 的唯一权威来源/生成关系仍需统一。
3. 字段表中的有效范围、userNum 上限，以及案例门限是生产规则还是示例，需按版本和场景确认；示例不能自动变成故障判据。
4. 版本解析冲突时展示来源并允许用户确认，不静默让 SYS_INFO 覆盖明确人工指定（已获用户认可）。
5. 已确认仅用户明确要求时进行同侪比较，筛选为同小区、分钟窗、排除目标 UE、相同 RB 区间及 Slot/起始符号位置，起始符号使用 ueSymPos。整分钟分桶还是滑动一分钟、非单符号情况的处理、是否另加资源限制、趋势差值公式仍属实现细节待定。比较结果须说明空间差异未受控。
6. 全覆盖遇时间预算或不支持字段时，建议返回部分完成报告与未覆盖清单，而不是阻断所有已完成事实。

## 4.1 本轮字段映射检查

- 当前新增字段表共 3435 条记录（未展开范围），152 条已填写归属：L1内部 33、L3 85、L2 16、L1测量 18；其余 3283 条归属留空。条目数不等于展开后的唯一 CSV 字段数。
- instBfSinrGain[0-3]、bfGainNumerator[0-3]、bfGainDenominator[0-3] 均标为 L1测量。因此不能继续将增益作为 L1_INTERNAL_DECISION 的固定示例，也不能凭增益变化直接推断内部算法输出异常。
- userNum 为“这个任务包含的码分用户个数”，归 L1内部；不能直接等同于整个 TTI/Slot 调度用户总数。crnti、freqUserRbStart、freqUserRbNum 按用户表归 L3。
- L1内部含时间、计数器、内部 ID 等技术字段，不等于每一项都代表算法判断结果；责任归属与字段角色应分开建模。
- symIdx、ueSymPos、symbolIdx 同时存在；用户已确认比较所需起始符号映射为 ueSymPos，不以 symIdx 或 symbolIdx 自动替代。
- uwTime 的新增说明为“时间（%y-%m-%d)”，与文档上方时间格式 %H:%M:%S 不一致，疑似笔误；日期仍为 uwDate，需明确修订该文字，不自动修改运行契约。
- 数组存在 [0~255]、[0-23]、[0-3] 等范围表示，解析器需规范展开到实际列并保留原条目出处。不能将所有短数组当作流；波束域需优先尊重显式含义及有效索引限制。
- isRsrp[0~255] 明确为波束级 RSRP，索引须小于接收天线数。这是新的有效下标约束，不等于普通“长度>=32”的临时分类规则。
- 存在 tag、len、preSinr、hbfFlag 等重复字段条目，其中一处有说明、其他处留空。不得用后续空白覆盖已有说明，也不得在缺少列位置/分段依据时自动将一个同名字段的语义分配给所有实例。
- 新增字段表缺少 Markdown 表头分隔行；后续规范化解析应处理或补齐格式。大量字段与空白条目也不宜作为单一检索片段，需按字段/字段族索引，避免当前截断摘要遗漏已填写语义。

## 5. 建议实施顺序

1. 合并已确认业务口径，修正文档中的 SQL、字段名和基础规则冲突。
2. 实现 ueLayerNum、流筛选、质量子类型及数据版本兼容，建立人工期望测试。
3. 扩展责任层、需求清单和字段核账，完善版本化映射。
4. 在现有受控 QueryPlan 上增加需求覆盖与有限补查，不先改成自由 SQL Agent。
5. 完善四层证据解释、表号映射、按问题粒度的缺测处理及输出格式兼容。
6. 最后调整 UI，使用实际规模数据验证导入、补查、内存、恢复与案例回放。
