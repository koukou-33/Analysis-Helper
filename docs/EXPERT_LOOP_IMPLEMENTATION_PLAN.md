# v3.4 专家循环实施计划

## 目标与范围
按主设计第5/7/8章迁移：plan → agent_loop → explain → report，保留ETL、质量、范围、特性及统计算子。旧动作绑定兼容图，新动作使用独立图版本。

## 实施顺序
1. 增加不可变证据包存储、哈希核验及报告来源索引。
2. 增加受约束的动态检索/QueryPlan调度器，持久化任务账本、去重、预算、停止原因；复用现有条件验证器。
3. 将现有确定性分析能力纳入agent_loop，冻结前完成视觉取证和目标核账。输出阶段只读包内材料，无返回分析边。
4. 绑定追问的父证据包、旧动作兼容和冻结后恢复；保留固定请求。
5. 补充冻结/恢复/动态查询/报告关联测试，运行现有回归，记录实际边界后提交推送。

## 验收
不能以队列为空或模型停止自述认定根因成立；输出失败不改写包。查询与知识版本可追溯，重试不清零预算，冻结后不访问查询/检索/视觉工具。旧数据规则回归保持不变。

## 本次实现
- `expert.v1` 新动作使用四节点单向图；已有未完成动作按旧图恢复，未知图版本拒绝静默迁移。
- `expert_tools.py` 提供 search/query/finish 契约，QueryPlan可组合全部现有算子；任务去重、执行状态和失败原因进入事务账本。finish只是结束工具选择，不自动确认目标或根因。
- 复用确定性特性/状态/覆盖及记录谓词验证，查询后重新核账已有指标目标；模型未配置仍生成事实报告。
- `analysis_bundle.py` 原子发布内容寻址证据包及解释/报告JSON，冻结时与读取时验证完整产物和摘要；报告失败后仅恢复输出，不再检索或查询。
- explain只允许包内已有假设和有数值依据的claims；不支持的新原因拒绝并标记输出降级。报告保留原始统计、目标/步骤/证据/摘要关联，并提供下载入口。
- `.env` 增加SRS_OUTPUT_RESERVE_SECONDS（默认15秒，受总预算限制），预留值随动作固化；模型调用计入累计预算。

## 实际能力边界
- 自主工具每动作最多6项选择；已有记录条件验证仍有独立的查询/规划次数预算。领域条件与时间关联必须使用已有可信规则，无法执行或未识别的目标保留不完整状态。
- 当前目标提取复用已有字段需求与特性目标机制，不承诺任意自然语言问题都可自动形成完备业务判据。初始AnalysisPlan保存本轮/父问题、范围、指标和完成约束；后续选择从实际证据中进行。
- 知识检索、通用算子选择已动态化；特性、会话状态及授权同侪工具作为确定性准备步骤复用。没有删除其来源/质量约束或自动开放跨会话与跨数据集分析。
- 报告以确定性统计和验证结果为主体，模型承担受约束的证据综合；未做真实模型质量或现场规模的生产验收。
- 新schema是本次可运行实现，设计中的通用逐结论语义证明仍受已实现规则和数值校验能力约束，不声称单靠引用即可证明因果。
